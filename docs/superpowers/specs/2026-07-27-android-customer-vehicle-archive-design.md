# Android 档案中心第二批：客户车辆只读档案设计

日期：2026-07-27  
状态：已获方向确认，待规格审阅  
范围：Android 档案根页新增客户车辆只读查询；不包含保险档案、任何档案写入或管理员修正。

## 1. 目标与边界

“档案”保留已完成的“维修历史”页签，并新增“客户车辆”页签。员工和管理员都可以查看当前登录企业的客户车辆记录、按客户/车牌/车型搜索、查看详情，并从详情进入当前或历史工单的只读详情。

本批严格只读：Android 不调用 `POST /api/customer-vehicles`，不导入、不新增、不编辑、不删除，也不显示任何管理员修正入口。保险档案、结算、返结算、作废、回执、导出和历史字段修正均不在范围内。

## 2. 服务端合同与授权

Android 使用已发布的 `GET /api/customer-vehicles`。请求只能携带当前认证会话的 Bearer Token；企业范围由服务端会话决定，客户端不得拼接企业 ID 或接受其他企业记录。

成功响应为 `{ vehicles: [...] }`。每条记录只映射以下可显示字段：`id`、`companyId`、`customer`、`phone`、`plate`、`car`、`vin`、`insurer`、`vehicleType`、`source`、`remark`。缺少 `id`、`companyId` 不等于当前会话企业、或根对象/vehicles 结构畸形时，整次远端响应视为畸形，不覆盖可用缓存。

服务端继续以 `customers` 权限裁决。401 触发现有认证失效与本地身份数据清理；403 显示“无权查看客户车辆档案”，不得泄露跨企业记录存在性；404、5xx、网络故障和畸形响应保留当前企业可解密缓存并显示可重试状态；协程取消原样传播。

## 3. 本地缓存、敏感数据与会话隔离

复用现有 Room v2 `customer_vehicles(companyId, recordId, encryptedPayload, updatedAt)` 表，不增加数据库迁移。完整客户车辆载荷在写入前通过 Android Keystore `StringCipher` 加密；手机号和 VIN 绝不以明文列、日志、测试输出或 UI test tag 存储。

缓存主键固定为 `companyId + recordId`。每次在线成功读取只替换当前企业的客户车辆缓存；外来企业响应、解密失败和损坏载荷都不能污染其他企业。登出、401、会话恢复失败和企业/账号切换继续经现有 `AuthenticatedDataCleaner` 清除该表。

在线时先显示当前企业的已解密缓存，再刷新远端完整列表；离线时禁止网络读取，只展示缓存并显示统一只读离线提示。离线且无缓存时显示诚实空状态。

## 4. Android 架构与导航

新增独立的客户车辆领域模型、`CustomerVehiclesApi`、`CustomerVehicleCache`、`CustomerVehiclesRepository` 和 `CustomerVehiclesViewModel`。仓储向 UI 暴露当前会话企业的快照流，负责缓存优先、在线刷新、错误映射和企业边界校验；ViewModel 仅持有查询词与可见记录的本地派生状态。

`Records` 根路由扩展为两个顶部分页：`维修历史` 与 `客户车辆`。两个页签各自保存查询词和滚动/导航栈语义；切换页签不重建或清空另一页数据。客户车辆卡片显示客户、车牌、车型和来源；详情显示完整允许字段，手机号和 VIN 仅在用户主动进入详情后显示。详情提供“查看关联工单”只读入口：若本地当前/历史摘要命中同一车牌则进入现有对应详情；没有已缓存的匹配工单时显示“暂无可查看的关联工单”，不发起写入或猜测远端数据。

`NavDisplay` 条目继续通过可更新状态引用读取客户车辆 UI state，避免已修复的筛选状态闭包问题再次出现。所有点击目标至少 48dp，状态栏安全区与底部五栏规则保持不变。

## 5. 测试与验收

测试先行覆盖：

1. HTTP 客户端正确使用 Bearer、解析成功响应、拒绝畸形/跨企业记录，并映射 401、403、404、5xx、网络与取消。
2. 加密缓存只按 `companyId + recordId` 读取和替换；缓存优先、离线不请求、401 清理、损坏密文删除和会话隔离均有 JVM 回归。
3. ViewModel 搜索客户/车牌/车型立即更新，刷新状态和缓存错误状态不清空已有记录。
4. Compose 测试覆盖页签切换、卡片/详情、无匹配、离线、无权限和无关联工单；验证页面没有写入按钮。
5. 最终执行 Node 全量测试、Android JVM 测试、Android 测试代码编译、Lint、Debug APK 构建，并生成真机安装包。只有本批 UI 需要额外排障时才启动模拟器；常规验收交给真机。

## 6. 非目标与风险控制

不修改 Cloudflare Functions、D1 schema、生产能力开关或网页端既有客户车辆写入流程。Android 的读取实现不改变服务端权限语义。管理员档案修正必须另行设计权限、版本冲突、审计和幂等写入；保险档案也必须作为独立批次设计，不能借本批接口或缓存模型旁路实现。
