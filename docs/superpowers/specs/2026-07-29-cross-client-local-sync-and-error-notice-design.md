# 跨端本机同步时间与可关闭错误提示设计

**日期：** 2026-07-29  
**状态：** 已确认设计，待规格审阅  
**范围：** 网页端、Windows 客户端、Android 客户端

## 目标

让使用者在三个端明确知道当前企业的数据最近何时成功从云端刷新；Android 提供统一、适合移动端的手动全量同步入口；网页与 Windows 中短期业务错误不再永久占据页面。

## 已确认决策

- 采用方案 A：同步时间是**本设备、本企业**的最近一次成功全量同步时间，不写入云端，也不追求跨设备同一时刻。
- 手动同步覆盖当前企业的工单、客户车辆、保险档案和已结算历史档案。
- 仅当四类数据均成功刷新时才更新同步时间；任意一类失败时保留现有数据和旧时间。
- 红色短期错误提示支持主动关闭，并在显示约 8 秒后自动消失；同一状态的后续成功操作立即清除错误。
- 表单字段校验错误、权限/业务规则说明和具有持续语义的静态警示不使用自动消失机制。
- 不新增 D1 migration、Room migration、服务端接口或业务权限。

## 同步状态模型

每个端维护按 `companyId` 隔离的本地记录：

```text
lastSuccessfulSyncAt: ISO-8601 时间戳 | null
syncing: Boolean
```

网页与 Windows 共用浏览器持久化存储；Android 使用现有本地安全存储能力。同步时间不含任何订单、客户或身份数据。切换企业时读取该企业自己的时间；退出登录不清空已保存时间。

全量同步开始时设置 `syncing=true`，并禁用同一入口。并行刷新工单、车辆、保险和历史档案；四项全部成功后写入当前时间并设置 `syncing=false`。失败时只设置 `syncing=false` 和短期错误提示，不覆盖 `lastSuccessfulSyncAt`。

## 交互与视觉

### 网页与 Windows

- 在工作台现有云端状态区域显示 `最近同步：今天 HH:mm`、`最近同步：昨天 HH:mm` 或完整日期时间；没有成功记录时显示 `尚未完成同步`。
- 保留已有刷新入口；其行为升级为当前企业全量同步，按钮在执行中显示同步态并防重复提交。
- 时间与在线状态采用低强调的辅助文字和现有蓝灰状态色，不增加醒目的独立卡片。

### Android

- 在“我的”页现有“数据同步”卡片中显示上述同步时间文案。
- 卡片右侧加入与设计系统一致的刷新图标按钮与“同步刷新”标签；同步中显示进度状态且不可重复点击。
- 离线时按钮保留，但触发后给出可关闭错误提示；既有缓存与最近成功时间保持可见。

### 错误提示

- 网页与 Windows 的网络、保存、刷新、下载等短期红色错误使用统一可关闭提示容器：右上角关闭按钮、可访问标签、约 8 秒自动消失。
- 用户关闭、同类成功操作、组件离开页面都必须清理对应临时错误。
- 对字段错误继续使用字段下方提示，用户修改相应字段后清除；不把这类提示转为自动关闭通知。
- Android 的同步失败沿用 Material Snackbar 语义，带关闭动作且不会阻塞页面；不会将网络失败误报为同步成功。

## 数据与兼容性

- 所有刷新继续调用现有认证、企业隔离和权限受控 API；不引入新的服务端写入。
- 全量同步失败时不得清空已缓存数据，也不得修改当前企业以外的本地记录。
- Windows 因与网页共享 React 界面，时间和临时错误行为必须完全一致。
- Android 必须继续支持 API 26+，不申请新权限；不启动模拟器，保留 JVM 测试、Android 测试代码编译、Lint、APK 构建与签名校验。

## 验收条件

1. 三端均能展示当前企业、本机持久化的最近成功同步时间。
2. Android “我的”页存在样式一致的“同步刷新”入口，执行当前企业四类数据的全量同步。
3. 四类刷新全部成功才更新时间；任一失败时旧时间和已缓存数据保留。
4. 网页与 Windows 的短期红色错误可以手动关闭、自动消失，并会在相同操作成功后清除。
5. 字段校验与持续性业务警示不因自动关闭机制而丢失。
6. 不改变 D1/Room schema、线上业务数据、权限结果或 API 合同。
